# Liveuta 관리자 디자인 시스템

이 문서는 `/admin/*` 전용 UI 기준이다. 일반 사용자 화면의 색상, 테마, radius,
breakpoint 규칙은 [공통 디자인 시스템](./design-system.md)을 따른다. 관리자 인터페이스는
데이터 확인과 반복 작업이 중심이므로, 장식보다 정보 밀도, 상태 가시성, 안전한 편집을 우선한다.

## 관리자 화면 범위

기존 관리자 메뉴와 업무는 다음과 같다.

| 경로 | 목적 |
| --- | --- |
| `/admin` | 관리자 이메일과 권한 레벨 확인 |
| `/admin/revalidate` | 메타데이터·채널·특집 캐시 작업 |
| `/admin/metadata` | 공개 메타데이터 조회 및 편집 |
| `/admin/member` | 멤버 관리 진입점; 레거시에서는 개발 중 placeholder |

향후 멤버·콘텐츠 관리 화면의 중심 UI는 **agGrid 데이터 그리드**와
**Lexical 리치 텍스트 에디터**로 둔다. 현재 저장소에는 Lexical 패키지가 있지만,
agGrid 패키지와 관리자 라우트 구현은 아직 없다. 실제 기능을 만들 때 데이터 계약과
편집 권한을 먼저 확정하고, 그 뒤 필요한 패키지와 기능을 추가한다.

## 관리자 셸

- 관리자 페이지는 일반 사이트의 헤더·푸터 흐름과 구분되는 전용 셸을 쓴다.
- 상단 헤더에는 `LU Admin`, 현재 페이지 또는 breadcrumb, 사용자 식별 정보,
  사이트로 돌아가는 동작을 둔다.
- `md` 이상에서는 고정 너비의 좌측 sidebar와 오른쪽 콘텐츠 영역을 사용한다.
  레거시 sidebar 폭은 `200px`였다. 새 구현에서는 `w-50` 또는 이에 해당하는 토큰으로
  일관되게 유지한다.
- `md` 미만에서는 sidebar를 숨기고 헤더의 메뉴 버튼으로 drawer를 연다. 항목 선택 후
  drawer를 닫고 포커스를 현재 페이지 제목 또는 콘텐츠로 이동한다.
- 콘텐츠 영역은 남은 너비를 채우고 `min-w-0`을 적용한다. 넓은 표가 있어도 sidebar와
  페이지 전체 폭을 밀어내지 않도록 그리드 컨테이너 내부에서 스크롤한다.
- safe area를 고려해 상단 헤더와 모바일 drawer를 배치한다. sticky/fixed 영역은 본문을
  가리지 않게 상단 여백을 확보한다.

예시 구조:

```tsx
<div className="min-h-dvh bg-background text-foreground">
  <AdminHeader />
  <div className="grid min-h-[calc(100dvh_-_var(--admin-header-height))] md:grid-cols-[12.5rem_minmax(0,1fr)]">
    <AdminSidebar />
    <main className="min-w-0 p-4 md:p-6">...</main>
  </div>
</div>
```

`--admin-header-height`는 실제 공통 헤더 치수를 정한 뒤에만 추가한다. 측정되지 않은
헤더 높이를 여러 화면에서 각각 하드코딩하지 않는다.

## 페이지 제목과 작업 구역

각 관리 페이지는 다음 위계를 유지한다.

1. breadcrumb 또는 상위 경로
2. 페이지 제목과 짧은 설명
3. 페이지 수준의 주요 작업
4. 필터·검색 도구 모음
5. 데이터 그리드, 편집 폼 또는 에디터
6. 저장 상태, 결과 개수, 페이지 이동 등 보조 정보

페이지 제목은 한 번만 `h1`로 사용한다. 표나 에디터를 둘러싼 카드에는 목적이 있을 때만
경계선과 배경을 적용하며, 모든 섹션을 중첩 카드로 만들지 않는다. 주요 작업은 한 구역에
모으고 위험한 작업은 일반 저장 동작과 시각적으로 구별한다.

## agGrid 데이터 그리드

agGrid는 멤버, 채널, 메타데이터처럼 행 단위로 찾고 비교하고 편집하는 관리자 화면의
표준이다. 그리드의 높이와 너비를 부모 레이아웃에 명시하고, 열 정의는 화면 기능 옆에 둔다.

### 툴바와 열

- 그리드 위에 검색, 필요한 범위의 필터, 결과 수, 새로고침 또는 생성 작업을 둔다.
- 정렬·필터가 가능한 열은 헤더에 상태를 표시하고 키보드로 조작할 수 있어야 한다.
- 이메일, 이름, 상태처럼 업무에 필요한 정보부터 배치한다. 내부 ID나 긴 JSON은 기본
  화면을 차지하지 않게 하고 상세 보기나 확장 영역에 둔다.
- 긴 값은 말줄임과 명확한 전체 값 확인 방법을 제공한다. 셀 안에서 원문을 수정하는 경우
  편집 가능 여부, 검증 오류, 저장 상태가 드러나야 한다.
- 행 작업은 일관된 마지막 열 또는 선택 행의 작업 메뉴에 모은다. `수정`, `저장`, `취소`,
  `삭제`의 위치와 활성 조건을 화면마다 바꾸지 않는다.
- 중요 열은 화면 크기에 따라 숨기거나 열 선택으로 제공한다. 주요 작업 열은 가로 스크롤 중
  찾기 쉬운 위치에 둔다.

### 크기와 반응형

- 넓은 화면에서는 남은 공간을 사용한다. 그리드를 고정 `max-width` 컨테이너 안에 가두지 않는다.
- `min-w-0`과 그리드 전용 `overflow-x-auto` 경계를 사용해 표가 전체 페이지를 넘치지 않게 한다.
- 좁은 화면에서는 모든 열을 축소하지 않는다. 우선 열을 남기고 나머지는 가로 스크롤,
  열 선택, 행 상세 패널 중 적절한 방식으로 접근하게 한다.
- 필터/검색 도구는 작은 화면에서 줄바꿈하거나 접을 수 있어야 하며, 버튼이 뷰포트 밖으로
  밀려나면 안 된다.
- 페이지네이션 또는 가상 스크롤을 쓸 때는 전체 결과 수와 현재 결과 범위를 알 수 있게 한다.
  중복된 무한 스크롤과 페이지네이션을 한 그리드에 동시에 적용하지 않는다.

### 행 상태와 접근성

- 로딩, 데이터 없음, 검색 결과 없음, 오류를 서로 다른 그리드 상태로 표시한다.
- 선택 행, hover 행, 키보드 포커스 행의 시각 상태를 구별한다.
- 상태는 색만으로 전달하지 말고 텍스트나 아이콘 설명을 함께 제공한다.
- 키보드 사용자는 그리드 진입, 셀 이동, 정렬, 편집, 취소, 행 작업을 수행할 수 있어야 한다.
- 변경 중인 행은 요청 중 상태를 표시하고 중복 제출을 막는다. 서버가 거부한 경우 오류를
  행 또는 셀 근처에 보여 입력값과 수정 위치를 보존한다.
- 권한 없는 필드와 행은 단순히 흐리게 보이는 상태에 의존하지 않는다. 허용된 작업만 UI에
  노출하고 API에서도 같은 권한을 다시 검증한다.

## Lexical 리치 텍스트 에디터

Lexical은 메타데이터 설명이나 공지처럼 서식이 필요한 콘텐츠에 사용한다. 입력 필드와
리치 텍스트 편집기를 혼동하지 않도록 에디터를 독립된 작업 영역으로 구성한다.

### 에디터 구성

- 에디터 위에 라벨, 설명, 저장 상태를 둔다.
- 서식 도구 모음에는 실제 지원 기능만 제공한다. 기본 도구는 제목/본문 스타일,
  굵게·기울임, 링크, 목록, 실행 취소/다시 실행으로 시작한다.
- 편집 가능한 본문은 명확한 테두리와 최소 높이를 갖고, 포커스와 읽기 전용 상태를
  식별할 수 있어야 한다.
- 표, 이미지, 임베드 등 추가 노드는 제품 콘텐츠 요구와 저장 계약이 정해진 뒤 추가한다.
  도구 모음에 동작하지 않는 버튼을 노출하지 않는다.
- 작은 화면에서는 도구 모음을 줄바꿈하거나 보조 메뉴로 접고, 본문 편집 영역은 화면 너비를
  채운다.

### 입력·저장 상태

- Lexical 상태를 도메인 계약에 맞게 직렬화하고, 로드/저장 경계에서 유효성을 검사한다.
  HTML을 저장한다면 허용 노드와 정화 정책을 함께 정의한다. 저장 포맷을 화면 컴포넌트에서
  임의로 바꾸지 않는다.
- 변경 전, 저장 중, 저장 성공, 저장 실패 상태를 구분한다. 자동 저장을 쓸 때는 마지막 저장
  시각과 실패한 변경이 남아 있음을 표시한다.
- 페이지를 벗어날 때 저장되지 않은 변경이 있으면 사용자에게 손실 가능성을 알려준다.
- 읽기 전용 권한에서는 도구 모음과 편집 입력을 비활성화하고, 콘텐츠는 읽을 수 있게 둔다.
- 키보드만으로 본문과 도구 모음을 이용할 수 있어야 한다. 툴바 버튼은 accessible name,
  pressed/disabled 상태를 제공하고 에디터에 visible focus를 표시한다.

## 폼과 위험 작업

- 필드는 라벨, 도움말, 오류 문구를 연결하고 오류를 입력 필드 가까이에 표시한다.
- 저장은 요청 중 중복 실행을 막고, 성공과 실패 피드백을 제공한다. 실패 시 사용자의 입력을
  보존한다.
- 캐시 초기화, 삭제, 권한 변경처럼 영향 범위가 큰 작업은 대상과 결과를 명시하고 필요한 경우
  확인 단계를 둔다.
- 오류 문구에 토큰, 비밀값, 내부 stack trace 등 민감한 응답 내용을 노출하지 않는다.

## 공통 상태와 시각 토큰

- 공통 의미 색상은 공통 디자인 시스템의 `bg-background`, `text-foreground`,
  `border-border`, `ring-ring`, `bg-destructive` 등을 사용한다.
- 관리자도 사용자가 선택한 5개 테마를 상속한다. 특정 관리자 화면에만 적용되는 별도 팔레트를
  만들지 않는다. 표에서 상태색이 필요한 경우 색상과 텍스트/아이콘을 함께 쓴다.
- 컨트롤, 카드, 패널은 공통 `rounded-control`, `rounded-card`, `rounded-panel`을 따른다.
- 포커스 링, disabled, pending, 성공, 오류 상태를 모든 관리자 작업에서 일관되게 표현한다.
- 빈 상태에는 다음 작업을 안내하고, 오류 상태에는 재시도 또는 복구 경로를 제공한다.

## 현재 확인된 구현 경계

- 레거시 관리자 셸은 `LU Admin` 헤더, `200px` sidebar, 홈/캐시/메타데이터/멤버 메뉴로
  구성되어 있다.
- 레거시 메타데이터는 key/value 표와 배너 이미지 URL 및 기본 영상 ID 편집 폼을 제공한다.
- 레거시 멤버 페이지는 placeholder이므로 새 기능과 열 정의는 별도 명세가 필요하다.
- 현재 저장소는 Lexical 패키지를 보유하지만 편집기 연결은 아직 확인되지 않았다.
- 현재 저장소에는 agGrid 의존성이 없다. AG Grid 기능과 라이선스 범위를 결정한 뒤 추가한다.
- 관리자 권한 검사는 메뉴 숨김으로 끝나지 않는다. 라우트 진입과 서버/API 작업에서 모두
  인증 및 권한을 확인한다. 자세한 API 마이그레이션 범위는
  [마이그레이션 체크리스트의 관리자 항목](./liveuta-migration-checklist.md#관리자)을 따른다.
